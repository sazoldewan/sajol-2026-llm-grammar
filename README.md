# Grammar of LLM-Generated Text — Reproducibility Release

MSc Thesis, International Software Systems Science (ISSS), Otto-Friedrich-Universität Bamberg
*How does the grammar of large language model-generated texts differ from that of
human-written texts in the English language?*

This repository contains the final scripts, generated model outputs, extracted
grammatical features, and statistical results used in the thesis. It does **not**
contain the copyrighted human-written source texts the study is built on — see
[Data licensing](#data-licensing--why-source-texts-are-not-redistributed) below.

## What the thesis does

The thesis compares the grammatical profile of human-written text against text
generated by large language models, across:

- **Three training stages** per model: Base, SFT (supervised fine-tuning), and
  DPO (direct preference optimization).
- **Three model families**: Mistral, Llama 3.1 / Tülu-3, and OLMo-2.
- **Two genres**: short news headlines (syntactically compressed) and academic
  paper introductions from the ACL Anthology (more elaborated prose).

35–36 grammatical features (part-of-speech rates, dependency-relation rates,
voice/aspect, tense, modality, structural complexity, stance) are extracted with
a Stanza/Universal-Dependencies pipeline from 1,000 human texts and 9,000
model-generated texts per genre (for the ACL genre, 8,693 of the 9,000
generations remained usable after post-processing). Three hypotheses are tested:

- **H1** — grammatical differences between training stages within a model family.
- **H2** — whether base models are grammatically closer to human writing than
  their SFT and DPO counterparts.
- **H3** — whether training-stage differences are larger in news headlines than
  in ACL introductions.

Cohen's *d*, Kruskal–Wallis, and Bonferroni-corrected Mann–Whitney U tests carry
the conclusions for all three hypotheses.

## Repository structure

```
data/
  human_corpora_manifests/   Non-redistributable source corpora, as manifests only
                              (IDs, publication/venue, date/year, URL — no article
                              or introduction text). See "Reconstructing the two
                              human corpora" below.
  generated_outputs/         master_{headlines,acl}_redacted.csv — one row per
                              text (human + all 9 checkpoints). Human rows have
                              their `text` field set to null (source text removed);
                              all generated-model text is included in full.
  features/                  features_{headlines,acl}.csv — the 35/36 extracted
                              grammatical features per text, the direct input to
                              the statistical analysis scripts. Purely numeric +
                              IDs, no source text of any kind.
  results/{headlines,acl,cross_genre}/
                              The CSVs and figures (.png) behind the thesis's H1/H2/H3
                              results: Cohen's d matrices, Kruskal-Wallis/Mann-Whitney
                              tables, and the H3 cross-genre comparison outputs.

scripts/
  corpus_construction/       Download/filter the two source corpora and build the
                              combined human+generated master datasets.
  generation/                The three generation scripts (headlines; ACL base;
                              ACL SFT/DPO) actually run on the HPC cluster.
  postprocessing/            Quality-check (diagnostic, non-destructive) and
                              cleaning (repetition truncation, sentence trimming,
                              prompt_style labeling) scripts.
  feature_extraction/        The Stanza/UD feature extractors for each genre.
  statistics/                H1/H2/H3 statistical analysis and the H3 cross-genre
                              comparison script.
  slurm_jobs/                The 18 actual SLURM job scripts run on the HPC
                              cluster (one per checkpoint), account paths
                              scrubbed to placeholders. See its own README.md.

requirements/                 Two separate environments: `analysis.txt` (local —
                               corpus tools, Stanza, stats) and `generation.txt`
                               (HPC — torch/transformers for model inference).

docs/                          MANIFEST.md (file-by-file provenance) and
                               LIMITATIONS.md (reproducibility caveats).
```

## Reconstructing the two human corpora

**Headlines:**
1. Run `scripts/corpus_construction/download_news_articles.py`. It streams
   `rjac/all-the-news-2-1-Component-one`, applies the year/title-length/
   article-length/listicle filters in the script, and stops at 1,000 qualifying
   articles — this reproduces the same 1,000 rows in the same order (the stream
   order is deterministic given the same dataset revision).
2. **Known gap, numbering verified:** the resulting file's rows need a
   sequential ID column (`HL_0001`–`HL_1000`) before it matches `prompt_id` in
   `data/features/features_headlines.csv` / the manifest here. No script in
   the original project performs this step — it was done ad hoc. To
   reproduce it:
   ```python
   df.insert(0, "prompt_id", [f"HL_{i+1:04d}" for i in range(len(df))])
   ```
   applied directly to the downloader's output, in row order, before any
   other processing. The *script* that originally did this is not recovered,
   but the resulting mapping *has* been independently confirmed: an actual
   HPC generation job log (`gen_llama_base`) shows `[HL_0001] Human: France's
   Sarkozy reveals his 'Passions' but insists no come-back on cards` — an
   exact match to row 1 of `Datasets/news_articles_1000.csv`, the original local
   corpus file (not included in this release, since it contains article text).
   See `docs/LIMITATIONS.md` item 3.
3. Cross-check your reconstruction against `data/human_corpora_manifests/
   headlines_source_manifest.csv` (publication, date, year, URL, word_count per
   `prompt_id`) — if your rebuilt corpus doesn't line up against this manifest
   row for row, the source dataset revision has likely changed since collection.

**ACL introductions:**
1. Run `scripts/corpus_construction/download_acl_corpus.py`. Unlike the
   headline downloader, this script assigns `prompt_id` itself
   (`ACL_0001`–`ACL_1000`, sequential in final filtered order) — no manual step
   needed.
2. Cross-check against `data/human_corpora_manifests/acl_source_manifest.csv`
   (`anthology_id`, year, venue, word_count per `prompt_id`).

## Running generation, feature extraction, and statistics

All scripts use hardcoded absolute paths from the original project (both local
`/Users/.../Thesis/...` paths and HPC `$WORK/...` paths) — **edit the path
constants near the top of each script before running them here.** This wasn't
cleaned up for this release; see `docs/LIMITATIONS.md`.

**1. Generation** (HPC, GPU required, `requirements/generation.txt`):
```bash
python scripts/generation/generate_headlines.py  --model_id <hf_id> --family <family> --stage <base|sft|dpo>
python scripts/generation/generate_acl_base.py    --model_id <hf_id> --family <family> --stage base
python scripts/generation/generate_acl_sft_dpo.py --model_id <hf_id> --family <family> --stage <sft|dpo>
```
Run once per checkpoint (9 runs per genre). `scripts/slurm_jobs/` has the
actual SLURM job script used for every single one of the 18 runs, with the
exact resource requests and arguments already filled in — use those directly
under `sbatch` (after replacing the `<hpc_account>`/`<hpc_user>` placeholders
with your own) instead of retyping the commands above by hand. The 9
checkpoints used:

| Family | Base | SFT | DPO |
|---|---|---|---|
| Mistral | `mistralai/Mistral-7B-v0.1` | `teknium/OpenHermes-2.5-Mistral-7B` | `NousResearch/Nous-Hermes-2-Mistral-7B-DPO` |
| Llama 3.1 / Tülu-3 | `meta-llama/Llama-3.1-8B` | `allenai/Llama-3.1-Tulu-3-8B-SFT` | `allenai/Llama-3.1-Tulu-3-8B-DPO` |
| OLMo-2 | `allenai/OLMo-2-1124-7B` | `allenai/OLMo-2-1124-7B-SFT` | `allenai/OLMo-2-1124-7B-DPO` |

None of the generation scripts pin a `revision=` when loading these models, so
by default they'd load whatever the current HEAD of each repo is. The exact
commit hash actually used for the thesis was retrieved from the Hugging Face
cache on the HPC cluster (`$HF_HOME/hub/models--.../snapshots/<hash>/`) after
the fact:

| Checkpoint | Revision (commit hash) |
|---|---|
| `mistralai/Mistral-7B-v0.1` | `27d67f1b5f57dc0953326b2601d68371d40ea8da` |
| `teknium/OpenHermes-2.5-Mistral-7B` | `24c0bea14d53e6f67f1fbe2eca5bfe7cae389b33` |
| `NousResearch/Nous-Hermes-2-Mistral-7B-DPO` | `ebec0a691037d38955727d6949798429a63929dd` |
| `meta-llama/Llama-3.1-8B` | `d04e592bb4f6aa9cfee91e2e20afa771667e1d4b` |
| `allenai/Llama-3.1-Tulu-3-8B-SFT` | `f2a0b46b0cfda21003c6141b1ff837b7e165524d` |
| `allenai/Llama-3.1-Tulu-3-8B-DPO` | `a7beb67e33ffd01cc87ac3b46cadc1000985b8db` |
| `allenai/OLMo-2-1124-7B` | `7df9a82518afdecae4e8c026b27adccc8c1f0032` |
| `allenai/OLMo-2-1124-7B-SFT` | **ambiguous — see below** |
| `allenai/OLMo-2-1124-7B-DPO` | **ambiguous — see below** |

7 of the 9 checkpoints had exactly one cached snapshot, so those revisions
are confirmed. `allenai/OLMo-2-1124-7B-SFT` and `allenai/OLMo-2-1124-7B-DPO`
each have **two** cached snapshots (`1de02c01.../606fc5cf...` and
`d6fa9c9f.../e34ea60a...` respectively) — meaning that repo was fetched at
two different points, and it's not possible to tell from the cache alone
which one was actually loaded during the runs that produced this release's
data. See `docs/LIMITATIONS.md` item 1 for what would resolve this.

All generation used greedy decoding (`do_sample=False`) for reproducibility.
Mistral's SFT/DPO checkpoints are independent third-party fine-tunes, not an
official continuation of the Mistral base model — unlike Llama/Tülu-3 and
OLMo-2, which are official same-lineage Base→SFT→DPO releases. Keep this
asymmetry in mind when comparing "family" effects across the three.

**2. Post-processing:**
```bash
python scripts/postprocessing/add_prompt_style.py       # ACL: labels stage->prompt_style
python scripts/postprocessing/clean_acl_outputs.py       # ACL: repetition truncation + sentence trim
python scripts/postprocessing/headline_quality_check.py  # headlines: diagnostic only, no rows changed
python scripts/postprocessing/acl_quality_check.py        # ACL: diagnostic only, no rows changed
```
Then rebuild the master files with
`scripts/corpus_construction/build_master_headlines.py` /
`build_master_acl.py`.

**3. Feature extraction** (`requirements/analysis.txt`):
```bash
python scripts/feature_extraction/extract_features_headlines.py
python scripts/feature_extraction/extract_features_acl.py
```
Produces `features_headlines.csv` / `features_acl.csv` (already included under
`data/features/` from the original run).

**4. Statistics:**
```bash
python scripts/statistics/stat_analysis_headlines.py
python scripts/statistics/stat_analysis_acl.py
python scripts/statistics/generate_h3_comparison.py   # run after both of the above
```
Produces the full contents of `data/results/{headlines,acl,cross_genre}/`
(already included from the original run).

**Verification of the statistics scripts.** The two `stat_analysis_*.py`
scripts in this release were prepared from the original analysis scripts by
removing exploratory code that is not part of the thesis. Both the original
and the release versions were run on `data/features/` in the same clean Linux
environment (Python 3.11, versions as in `requirements/analysis.txt`): all 12
CSV outputs were byte-identical, so this clean-up changed no result.
Compared with the stored results in `data/results/`, a re-run in that clean
environment reproduces all headline results and all Cohen's *d* values to
floating-point precision (relative differences below 1e-13). For the ACL
Kruskal–Wallis and Mann–Whitney tables, test statistics differ slightly
(at most 8.5 in *U*, relative differences below 1e-4), with the
corresponding *p*-values differing by at most 1.4% relative; no significance
decision changes.

## Known reproducibility limitations

See `docs/LIMITATIONS.md` for full detail. In short:

1. **Unpinned model revisions — resolved for 7 of 9.** None of the generation
   scripts pin a `revision=`, but the actual commit hashes were retrieved
   from the HPC's Hugging Face cache: 7 checkpoints had exactly one cached
   snapshot each (now recorded in the checkpoint table above) and are
   confirmed. `allenai/OLMo-2-1124-7B-SFT` and `-DPO` each have two cached
   snapshots, so which one was actually used remains ambiguous — see
   `docs/LIMITATIONS.md` item 1.
2. ~~Unpinned generation-environment package versions~~ — **resolved.** The
   exact HPC versions (`torch==2.12.0`, `transformers==5.11.0`,
   `accelerate==1.14.0`, `datasets==5.0.1`, `huggingface_hub==1.19.0`) were
   retrieved directly from `thesis_env` on the HPC cluster and are now pinned
   in `requirements/generation.txt`.
3. **Headline-ID assignment script not recovered.** The `HL_0001`–`HL_1000`
   `prompt_id` values are not produced by any script in the original project —
   they were assigned manually, in the row order the downloader produced. The
   *script* is still missing, but the resulting mapping has since been
   verified against an actual HPC generation job log (see item 3 above and
   `docs/LIMITATIONS.md`) — it is no longer just a plausible guess.
4. **All scripts use hardcoded absolute paths** from the original local
   machine and HPC account and will not run unmodified — edit the path
   constants near the top of each file first.
5. **Selection of the headline corpus is stream-order-dependent.** If
   the upstream `rjac/all-the-news-2-1-Component-one` dataset is ever
   re-uploaded or re-ordered, the same filters will not necessarily reproduce
   the same 1,000 articles.

## Data licensing / why source texts are not redistributed

Both source corpora consist of third-party copyrighted text (news articles and
academic paper introductions) collected and redistributed by other parties
under their own terms, not this thesis's own content. To avoid redistributing
that copyrighted text further:

- **No original article bodies or human-written headlines** are included.
  `data/human_corpora_manifests/headlines_source_manifest.csv` gives only
  `prompt_id`, publication, date, year, URL, and word count — enough to
  re-fetch or cite the originals, not to reconstruct them from this release.
- **No original ACL introduction text** is included.
  `data/human_corpora_manifests/acl_source_manifest.csv` gives only
  `prompt_id`, `anthology_id`, year, venue, and word count.
- **Human reference text is also redacted from the generated-output master
  files** (`data/generated_outputs/master_*_redacted.csv`): rows where
  `source == "human"` have their `text` field set to null. Only
  model-*generated* text is distributed in full, alongside every numeric
  feature and statistical result derived from the human texts.

If you need the underlying source text for verification, obtain it directly
from `rjac/all-the-news-2-1-Component-one` and `KRLabsOrg/acl-anthology-md` on
Hugging Face using the `prompt_id`/`anthology_id` mappings in the manifests.
