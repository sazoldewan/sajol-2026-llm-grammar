# Grammar of LLM-Generated Text — Replication Package

Code and data for the MSc thesis *How does the grammar of large language
model-generated texts differ from that of human-written texts in the English
language?* (Dewan Asikuzzaman Sajol, MSc International Software Systems
Science, University of Bamberg, 2026).

The thesis compares human-written texts with texts generated by nine model
checkpoints (Mistral, Llama 3.1 / Tülu-3 and OLMo-2, each at the Base, SFT and
DPO stage) in two genres: news headlines and ACL paper introductions.

## What is in this repository

| Folder | Contents |
|---|---|
| `data/generated_outputs/` | All model-generated texts (9,000 per genre). The human texts are removed because they are copyrighted. |
| `data/human_corpora_manifests/` | A list of the human source texts (ID, source, date, URL) without the texts themselves. |
| `data/features/` | The grammatical features extracted from every text. This is the input to the statistics. |
| `data/results/` | The tables and figures reported in the thesis. |
| `scripts/` | All code, in the order it is run (see below). |
| `requirements/` | Python packages: `analysis.txt` (normal computer) and `generation.txt` (GPU cluster). |
| `docs/` | `MANIFEST.md` (where each file comes from) and `LIMITATIONS.md` (details on reproducibility). |

## Before you start

Every script contains file paths from the original project near the top
(for example `/Users/.../Thesis/...` or `$WORK/...`). **Open each script and
change these paths to your own folders before running it.**

## Quick option: reproduce only the statistics

The features are already included, so the statistics can be re-run on a normal
computer:

```bash
pip install -r requirements/analysis.txt
python scripts/statistics/stat_analysis_headlines.py
python scripts/statistics/stat_analysis_acl.py
python scripts/statistics/generate_h3_comparison.py
```

This recreates the files in `data/results/`.

## Full reproduction, step by step

### Step 1: Download the human texts

**News headlines**

```bash
python scripts/corpus_construction/download_news_articles.py
```

This downloads *All the News 2.0* (`rjac/all-the-news-2-1-Component-one` on
Hugging Face), keeps articles that pass the filters in the script, and saves
the first 1,000 as `news_articles_1000.csv`.

Then give each row an ID, `HL_0001` to `HL_1000`, in the order of the file.
In the original project this was done with a short separate command that was
not kept, so this repository has no script for it; this one command does the
same:

```bash
python -c "import pandas as pd; df = pd.read_csv('news_articles_1000.csv'); df.insert(0, 'prompt_id', [f'HL_{i+1:04d}' for i in range(len(df))]); df.to_csv('news_articles_1000.csv', index=False)"
```

**ACL introductions**

```bash
python scripts/corpus_construction/download_acl_corpus.py
```

This downloads the introductions (`KRLabsOrg/acl-anthology-md` on Hugging Face)
and assigns the IDs `ACL_0001` to `ACL_1000` itself.

**Check:** compare your files with
`data/human_corpora_manifests/headlines_source_manifest.csv` and
`acl_source_manifest.csv`. If the rows do not match, the dataset on Hugging
Face has probably changed since the texts were collected.

### Step 2: Generate the model texts (GPU needed)

Install `requirements/generation.txt` on a GPU machine. Each script is run once
per checkpoint (9 runs per genre):

```bash
python scripts/generation/generate_headlines.py  --model_id <hf_id> --family <family> --stage <base|sft|dpo>
python scripts/generation/generate_acl_base.py    --model_id <hf_id> --family <family> --stage base
python scripts/generation/generate_acl_sft_dpo.py --model_id <hf_id> --family <family> --stage <sft|dpo>
```

The easiest way is to use the ready-made job files in `scripts/slurm_jobs/`
(one per run, with all arguments filled in). Replace `<hpc_account>` and
`<hpc_user>` with your own values and submit them with `sbatch`.

All generation used greedy decoding (`do_sample=False`). The checkpoints and
the exact model versions (Hugging Face commit hashes) used:

| Family | Stage | Checkpoint | Version (commit hash) |
|---|---|---|---|
| Mistral | Base | `mistralai/Mistral-7B-v0.1` | `27d67f1b5f57dc0953326b2601d68371d40ea8da` |
| Mistral | SFT | `teknium/OpenHermes-2.5-Mistral-7B` | `24c0bea14d53e6f67f1fbe2eca5bfe7cae389b33` |
| Mistral | DPO | `NousResearch/Nous-Hermes-2-Mistral-7B-DPO` | `ebec0a691037d38955727d6949798429a63929dd` |
| Llama | Base | `meta-llama/Llama-3.1-8B` | `d04e592bb4f6aa9cfee91e2e20afa771667e1d4b` |
| Llama | SFT | `allenai/Llama-3.1-Tulu-3-8B-SFT` | `f2a0b46b0cfda21003c6141b1ff837b7e165524d` |
| Llama | DPO | `allenai/Llama-3.1-Tulu-3-8B-DPO` | `a7beb67e33ffd01cc87ac3b46cadc1000985b8db` |
| OLMo-2 | Base | `allenai/OLMo-2-1124-7B` | `7df9a82518afdecae4e8c026b27adccc8c1f0032` |
| OLMo-2 | SFT | `allenai/OLMo-2-1124-7B-SFT` | one of two versions (see `docs/LIMITATIONS.md`) |
| OLMo-2 | DPO | `allenai/OLMo-2-1124-7B-DPO` | one of two versions (see `docs/LIMITATIONS.md`) |

The scripts load the latest version of each model by default. To use exactly
the versions above, add `revision="<hash>"` where the script loads the model.

### Step 3: Clean the generated texts

```bash
python scripts/postprocessing/add_prompt_style.py
python scripts/postprocessing/clean_acl_outputs.py
python scripts/postprocessing/headline_quality_check.py
python scripts/postprocessing/acl_quality_check.py
python scripts/corpus_construction/build_master_headlines.py
python scripts/corpus_construction/build_master_acl.py
```

The two quality-check scripts only report problems; they do not change any
rows. The last two scripts combine the human and generated texts into one file
per genre.

### Step 4: Extract the grammatical features

```bash
python scripts/feature_extraction/extract_features_headlines.py
python scripts/feature_extraction/extract_features_acl.py
```

This creates the files in `data/features/`.

### Step 5: Run the statistics

The same three commands as in the quick option above.

## How well do the results reproduce?

Re-running the statistics on the included features in a clean environment
(Python 3.11, packages as in `requirements/analysis.txt`) gives the same
headline results and Cohen's *d* values as those stored in `data/results/`
(differences below 1e-13, i.e. only rounding). For the ACL
Kruskal–Wallis and Mann–Whitney tables, the test statistics differ very
slightly (*p*-values by at most 1.4% relative), and no result changes from
significant to non-significant or the other way round.

## Things to keep in mind

- **Model versions:** for OLMo-2 SFT and DPO, two versions were downloaded
  during the project, and it is not certain which one produced the texts.
- **Headline sample:** the downloader takes the first 1,000 matching articles.
  If the dataset on Hugging Face is re-uploaded in a different order, a
  different sample may come out.
- **Mistral:** the Mistral SFT and DPO models are fine-tuned by other groups,
  not by Mistral AI, unlike the Llama/Tülu-3 and OLMo-2 checkpoints.

More detail on all of these is in `docs/LIMITATIONS.md`.

## Data and copyright

The human texts come from two third-party corpora on Hugging Face:
*All the News 2.0* (`rjac/all-the-news-2-1-Component-one`; 1,000 articles from
7 publications, 2016–2019) and ACL Anthology introductions
(`KRLabsOrg/acl-anthology-md`; 1,000 introductions, 2015–2020). Because these
texts are copyrighted, this repository does not include them: the manifests
list only IDs and metadata, and the human rows in
`data/generated_outputs/` have an empty `text` field. Use the download scripts
in Step 1 to get the texts yourself.

## Software versions

- **Analysis** (download, feature extraction, statistics): Python 3.11.7,

- **Generation** (GPU cluster): Python 3.12.0, PyTorch 2.12.0,
